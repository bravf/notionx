# 多用户账号与邀请码

## 启动与升级

首次启动前设置 ADMIN_PASSWORD（至少 8 字符）和可选 ADMIN_USERNAME（默认 admin），然后按原有方式启动应用。初始管理员首次登录必须修改密码。未配置初始密码时禁止匿名访问，不开放网页抢先创建管理员入口。

从旧版升级可以继续使用服务器已有的 APP_PASSWORD 初始化管理员，用户名默认为 admin。数据库启动时以事务迁移到结构版本 2，原有内容、实体 ID 和版本号保留并归入管理员私人空间。首次改密后环境变量不会再覆盖账号密码。

升级前必须做 SQLite 一致性备份。需要回滚旧版代码时，必须同时恢复升级前的整库备份，不能让旧版直接操作新版数据库。

## 注册与管理

- 管理员在侧栏“账号与邀请码”生成邀请码。默认一码一人、7 天有效，可设置 1–90 天。完整邀请码仅生成时显示一次，请复制保存。
- 管理员可撤销未使用邀请码、关闭全部新注册、停用或启用账号，以及重置其他账号密码。
- 用户通过邀请码、用户名和密码注册，不需要邮箱。用户名为 3–32 位字母、数字或下划线，大小写不敏感；密码为 8–128 个字符；昵称选填。
- 注册失败不会消耗邀请码；注册账号、创建空间和消耗邀请码在同一事务完成。
- 每个新账号拥有空白私人空间。页面、数据表格、搜索、回收站、版本号、内容备份恢复、浏览器草稿和最近访问均按账号/空间隔离。管理员界面不提供读取其他用户正文的入口。
- 用户在“设置与备份”修改密码和退出。忘记密码联系管理员；重置生成一次性展示的临时密码，下次登录必须修改。
- 重置密码和停用账号立即撤销该账号原有登录。主动修改密码撤销其他设备的登录。会话有效期 30 天，服务重启保留有效登录。

## 配置

| 环境变量       | 用途                                       |
| -------------- | ------------------------------------------ |
| ADMIN_USERNAME | 首次初始化管理员用户名，默认 admin         |
| ADMIN_PASSWORD | 首次初始化管理员临时密码，至少 8 字符      |
| APP_PASSWORD   | 兼容旧版，仅首次初始化时作为管理员临时密码 |
| COOKIE_SECURE  | HTTPS 生产部署设置为 true                  |

已建立账号后，修改环境变量不会重置数据库中的用户密码。不要把真实密码提交到 Git。

## 存储与备份

密码以带随机盐的 scrypt 保存，邀请码和会话令牌仅保存哈希；登录、注册和改密接口设有频率限制。邀请码和临时密码只能在生成时复制，列表不提供原文找回。

用户 JSON 备份仍使用 schemaVersion 1，只包含当前空间内容，不含账号、密码和邀请码。服务器整库备份包含所有账号和空间，用于灾难恢复，需妥善保管。

## 验证

npm test 包含账号、邀请码并发兑换、独立空间、旧库迁移、HTTP 权限及会话失效测试。

浏览器测试必须针对专用数据库和账号。先在浏览器完成管理员首次改密，再设置 TEST_URL、TEST_USERNAME 和 TEST_PASSWORD 后运行 npm run test:e2e。不要对个人实际使用的空间运行备份恢复测试。
